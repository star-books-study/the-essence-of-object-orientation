# 1장. 협력하는 객체들의 공동체

- 객체지향의 목표는 실세계를 모방하는 게 아니라 오히려 고객과 사용자를 만족시킬 수 있는 신세계를 창조하는 것
- 그러나 실세계에 대한 비유가 객체지향 학습에 매우 효과적이므로 이번 장에서는 이 방법을 사용


## 협력하는 사람들
- 커피 주문은 역할, 책임, 협력이라는 세 가지 개념이 어울려 조화를 이루며 만들어진 것
  - `주문하는 손님` `주문을 받는 캐시어` `커피를 제조하는 바리스타` **역할**이 존재하고, 손님에게 커피를 제공하기 위해 **협력**하는 과정에서 맡은 바 **책임**을 다한다.

### 요청과 응답으로 구성된 협력
- 하나의 문제를 해결하기 위해 다수의 역할이 필요하기 때문에 한 사람에 대한 요청이 다른 사람에 대한 요청을 유발
- 따라서 요청은 연쇄적으로 발생하고 응답 역시 반대 방향으로 연쇄적으로 전달
- 요청과 응답을 통해 서로 협력

### 역할과 책임
- 특정한 역할 ➡️ 특정한 책임

## 역할, 책임, 협력
### 기능을 구현하기 위해 협력하는 객체들
- 객체지향을 실세계의 모방으로 표현하면
  - 사람 = 객체
  - 에이전트의 요청 = 메시지
  - 에이전트가 요청을 처리하는 방법 = 메서드
 
### 역할과 책임을 수행하며 협력하는 객체들
- 성실한 객체 시민은 다른 객체와도 적극적으로 협력
- 적절한 객체에 적절한 책임을 할당하는 것이 중요
  - 책임이 불분명한 객체는 애플리케이션의 미래 역시 불분명하게 만듦
- 객체의 역할이 가진 특징
  - 여러 객체가 동일한 역할을 수행할 수 있다
  - 역할은 대체 가능성을 의미한다
  - 각 객체는 책임을 수행하는 방법을 자율적으로 선택할 수 있다
  - 하나의 객체가 동시에 여러 역할을 수행할 수 있다.

## 협력 속에 사는 객체
- 협력의 품질을 결정하는 것은 결국 객체
- 객체가 가져야 할 덕목
  - 충분히 '협력적'이어야 함 (개방성)
    - 다른 객체의 요청에 충실히 귀 기울이고 다른 객체에게 적극적으로 도움을 요청할 정도로 **열린 마음**을 지녀야 한다
  - '자율적'이어야 한다 (자율성)
    - 어떤 방식으로 응답할지는 객체 스스로 판단하고 결정

  ### 상태와 행동을 함께 지닌 자율적인 객체
  - 객체의 자율성은 객체의 내부와 외부를 명확하게 구분하는 것으로부터 나온다
  - 다른 객체가 '무엇'을 수행하는지는 알 수 있지만 '어떻게' 수행하는지에 대해서는 알 수 없다
  - 전통적인 개발 방법과 다르게 객체지향에서는 상태(데이터)와 행위(프로세스)를 하나의 틀 안에 묶어 놓음으로써 객체의 자율성을 보장한다
    - 객체의 관점에서 자신의 상태를 직접 관리하고 상태를 기반으로 스스로 판단하고 행동할 수 있다
  - 자율적인 객체로 구성된 공동체는 유지보수가 쉽고 재사용이 용이하다
 

### 협력과 메시지
- 객체지향의 세계에서는 오직 한 가지 의사소통 수단만이 존재 ➡️ 메시지
- 한 객체가 다른 객체에게 요청하는 것을 `메시지를 전송`한다고 말하고 다른 객체로부터 요청을 받는 것을 `메시지를 수신`한다고 한다
- 메시지를 전송하는 객체를 `송신자`, 메시지를 수신하는 객체를 `수신자`라고 부른다

### 메서드와 자율성
- 수신자는 먼저 수신된메시지를 이해할 수 있는지 여부를 판단한 후 미리 정해진 자신만의 `방법`에 따라 메시지 처리
- 객체가 수신된 메시지를 처리하는 방법을 `메서드`라고 함
- 어떤 객체에게 메시지를 전송하면 메시지에 대응되는 특정 메서드가 실행된다 ➡️ 메시지를 수신한 객체가 실행 시간에 메서드를 선택할 수 있다
  - 프로시저 호출에 대한 실행 코드를 컴파일 시간에 결정하는 다른 프로그래밍 언어와 구분됨
- 메시지와 메서드를 분리하는 것은 객체의 자율성을 높이는 핵심 메커니즘
  - 커피 제조를 요청한 캐시어가 바리스타가 커피를 제조하는 구체적인 방법에는 관여하지 않듯이

## 객체지향의 본질
### 객체를 지향하라
- 객체지향하면 클래스를 가장 잘 떠올리지만, 클래스는 협력에 참여하는 객체를 만드는 데 필요한 구현 메커니즘일 뿐 객체지향의 중심에는 객체가 위치
- 객체 지향의 핵심은 적절한 책임을 수행하는 역할 간의 유연하고 견고한 협력 관게를 구축하는 것
- 클래스의 구조와 메서드가 아니라 객체의 역할, 책임, 협력에 집중하라.
